# CLAUDE.md

Guidance for Claude (and other AI agents) working in this repository.

## What this repo is

David W. Thomas's personal AGI research collection: notes, reports, paper summaries, and design
documents about what a human-like general intelligence would require. It is a research repo, not
(yet) a code project. All documents live in `docs/` as Markdown.

Current documents:

- `docs/AGIDesignChecklist.md`: checklist of capabilities an AGI design should have
- `docs/AGIDesignChecklistReview.md`: Claude's review of the checklist (citation check, claim check, suggestions)
- `docs/InnateCognitionReport.md`: report on innate human cognition and what it implies for AGI
- `docs/MilinkovicAruBiologicalComputationalismSummary.md`: summary of Milinkovic & Aru (2025)

## Provenance (most important rule)

Each document says who or what wrote it. Never present AI-generated text as David's own writing.

- Existing docs carry a `> **Provenance:**` note under the title saying they were generated by
  SciSpace. Keep these notes when you edit.
- Any document you create gets a provenance note right under its title, in the same style:
  `> **Provenance:** Generated by Claude (Anthropic) from prompts written by David W. Thomas. The text is Claude output, not original writing by David W. Thomas.`
- If you substantially edit a document someone else generated, add that to its provenance note
  (e.g. "Revised by Claude (Anthropic) on YYYY-MM-DD.") rather than replacing it.
- A paper summary must say it is a summary, not the paper itself.

## Citations

- Cite real, verifiable sources. Include a DOI or URL whenever one exists.
- Never invent a paper, author, quote, finding, or DOI. If you can't verify a source, leave it out
  or mark it clearly as `[unverified]`.
- Use numbered references `[n]` in the text with a `## References` list at the end of the document.
- When you draw on an existing doc's references, keep the same source and don't renumber the other
  document.

## Writing style

- Markdown, with one `#` title per file and `##` sections.
- File names are PascalCase, descriptive, `.md`, in `docs/` (e.g. `docs/WorldModelsSurvey.md`).
- Keep the difference between evidence, interpretation, and speculation clear, and say when
  something is contested.
- When you add a document, also add it to the list in `README.md` and in "Current documents" above.

## Git workflow

- Work on a branch, never commit directly to `main`.
- Open a pull request for David to review. In the PR description, summarize what changed and list any
  sources you couldn't verify.
- Use small, focused commits with descriptive messages.

## Unattended runs

Tasks often run in the cloud while David is away and can't answer questions. If the request is
ambiguous, pick the most reasonable reading, do the work, and list your assumptions and open
questions in the PR description instead of stopping.
