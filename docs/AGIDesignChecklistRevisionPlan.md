## Session 2 — Epistemic Framing

**Review recommendations addressed:** #1 (mark opinions as opinions), #5 (update innate-priors claims).

### Changes to AGIDesignChecklist.md

**Core principle**

- Rephrase *"A human-like general system would need inductive structure…"* → *"We hypothesise that a human-like general system would need…"* (review: `[Opinion as fact] [Contested]`)
- Add one sentence giving the opposing view: the "Bitter Lesson" (Sutton) / Botvinick et al. argument that structure should be learned rather than built in, consistent with `[1, 2]` in the review.

**§1 Innate or built-in representational primitives**

- After the paragraph ending *"…keeping the case for hard-wired primitives empirically open"* (added in Session 1), add a sentence flagging that the question is **open and contested**, not settled in favour of hard-wired priors.
- Numerical representation: add a note that the innate-number-sense claim is contested by Leibovich et al. [33] (already cited in §1 after Session 1).
- Agent/belief-tracking: add a note that early false-belief paradigms have replication problems (Kulke et al. [32]).

**§2 Learning and abstraction**

- *"mature symbolic abstraction is developed through experience, language, and culture"* — add qualification: C28 (Revencu & Csibra) doubts that language alone explains productive thought; Lake & Baroni [36] showed meta-learning can achieve compositionality without built-in symbolic machinery.
- *"The checklist should therefore require both preconfigured structure and learning-driven refinement"* — rephrase as a hypothesis: *"One design strategy is to combine preconfigured structure with learning-driven refinement; another is to derive structure entirely from training curricula [36]."*

**Bottom line**

- *"The strongest design lesson is … build the right inductive biases…"* — rephrase as *"One synthesis of this evidence is: build the right inductive biases…"*
- Add one sentence: *"The opposing view holds that general methods that scale with compute have historically beaten hand-built structure [1, 2], and the right balance remains an open empirical question."*

## Session 4 — Missing Capabilities

**Review recommendations addressed:** #2 (alignment/safety/interpretability), #8 (energy/compute), #9 (developmental schedule), #10 (consciousness scope note), Section 3.1 (full table of missing items), Section 3.4 (biological computationalism link).

### New items to add to AGIDesignChecklist.md

**New section: Alignment and safety** (absorbing items moved in Session 3)

- *Alignment target:* Specify what the system aligns to — instructions, intentions, interests, or values — and how conflicts between stakeholders are resolved. (Gabriel 2020 [22 in review])
- *Safety under exploration:* Exploration is bounded by safety constraints; the system avoids reward hacking and degrades gracefully under distribution shift. (Amodei et al. [23 in review])
- *Interpretability / inspectability:* Internal states relevant to goals, beliefs and uncertainty can be inspected by external tools, not only through the system's own explanations. (mechanistic interpretability [24 in review])

**§4 Agency — additions**

- *Intrinsic motivation (specified):* State the intrinsic-motivation signal (e.g. learning-progress / prediction-error) and show it improves exploration over an extrinsic-reward baseline. Cite Oudeyer & Kaplan [40] typology.
- *Loss of plasticity:* Retains old skills **and** keeps the ability to learn new ones over a long task sequence. Cite Dohare et al. [38].
- *Embodiment (clarified):* Decide and state whether physical embodiment is required or whether simulated/tool-based action is sufficient, and give the reason.

**§5 Memory — addition**

- *Developmental schedule / curriculum:* Specify the learning schedule: what is learned first, in what environment, with what exploration–exploitation balance. Cite Gopnik [41].

**Energy and compute efficiency** (new §4 item or standalone requirement)

- State an energy/compute budget for learning and inference; report sample efficiency and energy use alongside accuracy. Cite brain 20 W baseline [25 in review] and training-cost literature [26 in review].
- Add a brief substrate-assumptions note: state whether the architecture assumes hardware independence, or whether neuromorphic/analog substrates are a live design variable (links to `docs/MilinkovicAruBiologicalComputationalismSummary.md`).

**Consciousness and moral-status scope note** (preamble or new §9)

- Add a short note taking an explicit position: whether machine consciousness is a design target, a non-target, or an open risk.
- Cite Butlin et al. [31 in review] (computational functionalism) and Seth [32 in review] (biological-substrate view), contrasted with Milinkovic & Aru [33 in review] (biological computationalism summary already in repo).

## Session 5 — Testability

**Review recommendations addressed:** #3 (make §8 testable), Section 3.3 (concrete measurable versions of vague items).

### §8 Evaluation criteria — overhaul

Replace the current eleven untestable bullet points with versions that each include: a **task or benchmark**, a **comparison baseline** (usually human performance on the same task), a **threshold or metric**, and a **contamination control** where relevant.

| Current item | Measurable version |
|---|---|
| Generalize from sparse data to structurally new cases | ARC-style procedurally generated tasks [44,45]: ≥ X% from ≤ N demonstrations vs. humans given same demonstrations; contamination control: tasks created after training cutoff |
| Transfer relation or skill across modalities | Systematic-generalization splits: test combinations of known primitives never in training [36]; score vs. human performance on same splits |
| Learn from interaction rather than static datasets | N-shot learning speed in a new domain vs. freshly initialized network |
| Explain and use causal structure under interventions | Predict results of interventions on held-out causal graphs; score association / intervention / counterfactual queries separately [43] |
| Learn continuously without losing prior capabilities | Average accuracy on earlier tasks (forgetting) **and** learning speed on each new task vs. freshly initialized network [37,38] |
| Distinguish familiar surface patterns from deeper relational similarity | Analogy tasks with surface-misleading distractors; score separately |
| Know when uncertain or wrong | Expected calibration error + selective-prediction accuracy at fixed coverage on in-distribution and shifted data (merge with §7 uncertainty item) |
| Coordinate with humans whose goals and beliefs differ | Theory-of-mind battery including perturbed variants that defeat surface-cue strategies [review ref 11] |
| Develop new abstractions not in training data | Tasks created after training cutoff with documented contamination check |
| Overall score | Report a level on the performance × generality × autonomy taxonomy [46] rather than a binary "true generality" |

**Heading change:** rename *"Evaluation criteria for 'true' generality"* → *"Evaluation criteria and benchmarks"* (the review flags "true" as a loaded term).
